# SnapGene DNA Design 发布版迭代需求清单（面向可发布版本，2026-08-19）

- 定位：**本迭代作为可发布版本**（公开 GitHub 目标）。以下全部要求按"发布级"执行，与既有审查任务（RG2-P2-01~06、开发者意见 3 条）共同构成下轮审核的强制输入。
- 来源：开发者（实际使用意见 + 发布决策）+ 审查AI B 的 primer3 深度审查结论（第 4 层 slide-retry 实证）。
- 状态：待开发方执行；下轮审核逐项验证。

---

## 1. 背景与定位

1.1 本版本将作为可发布版本，生物学结果将被真实科研用户采信——**生物学准确性与用户知情权是最高优先级**，高于功能数量与开发速度。
1.2 前几轮审查已确立的底线（不得回退）：隐私 consent 一次性绑定（RG-P0-01 已修复）、无静默降级（primer3 三层重试 + NOT Primer3 标注）、provenance 条件必填、版本单一来源。
1.3 本清单在 v0.9 Spec 三条铁律（算法正确性、实验可行性、权威溯源）之上新增两条铁律：**用户知情权与操作透明**、**生物学准确性优先**。

---

## 2. 总体原则（五铁律）

| # | 铁律 | 要求 |
|---|---|---|
| 1 | 算法正确性 | 数值必须算法计算，AI 不凭感觉、不硬编码经验值到输出 |
| 2 | 实验可行性 | 方案必须过经验规则库过滤，禁止理论可行实际没人做的方案 |
| 3 | 权威溯源 | 知识/规则/默认参数必须带来源（文献、数据库、官方文档链接） |
| 4 | **用户知情权与操作透明（新增）** | 关键操作**先询问用户并明确告知**；AI 的每个操作**透明可见**（后端、参数、来源、降级标记）；**非常规处必须询问** |
| 5 | **生物学准确性优先（新增）** | 所有输出可追溯到算法与来源；物种适用性警告；不静默降级；结果报告供人阅读 |

## 3. primer3 第 4 层 slide-retry（本迭代核心修复）

### 3.1 采纳 AI B 实证路径
- 位置：`scripts/primer_design_engine.py`（在现有三层重试之后、报错/降级之前增加第 4 层）。
- 参数（AI B 实验 B8/B9 验证可行）：
  - 释放 `SEQUENCE_FORCE_LEFT_START`/`SEQUENCE_FORCE_RIGHT_START`：允许引物 5' 端在 `[0, min(25, len/4))` 内滑动；
  - `PRIMER_PRODUCT_SIZE_RANGE` 放宽为 `[n-100, n+100]`；
  - Tm 窗口用 relaxed 50–72°C；
  - GC 约束原则上不动（保持 20–80%），避免放松质量底线；若确需放宽须走询问机制（见 §4）。
- 成功输出：报告 `boundary_offset_5p/3p`（引物起点相对扩增子边界的偏移 nt），`primer3_retry_note="slide-retry"`，保留 explain 计数。
- 失败输出：**替代建议而非裸报错**——如"扩增子 5' 端外扩 20–40 bp 可解"或"改用内部引物对"；`--require-primer3=True` 保留 `Primer3CoreError` 但必须附可执行路径。

### 3.2 回归测试（真实 primer3_core 门控）
- A 组：尾巴案例 → binding-only 成功（0→2 对）；
- B 组：97% GC 端部 → slide-retry 成功且 `boundary_offset` 正确（复现 B9：L0=CCGGCGCGACGTGCATAC 等 3 对）；
- C 组：纯 poly-G 端部 → 给出替代建议文本而非空失败；
- 断言：无静默降级（回退必须带 NOT Primer3 标注）。

### 3.3 与三层重试的关系
- 保留开发方已实现且经验证有效的三层（tailed→binding-only→relaxed-Tm）与全部留痕（`primer3_retry_note`/`primer3_failure`/explain 计数/`_backend_source`）；
- 修正 relaxed 层的失效声明：文档如实说明"relaxed 只放宽 Tm 超窗场景；GC 超界需走第 4 层或询问用户"。

## 4. 用户知情权与询问机制（本迭代重点，须实现为代码级行为）

### 4.1 询问的时机（常规，自动化流程中显式列出并确认）
- 引物设计前：确认参数窗口（Tm 范围、产物长度、GC 范围）、是否允许滑动；
- 后端选择：确认使用真实 Primer3 / Cas-OFFinder / 模型，还是（不可避免时）降级路径；
- 在线提交前：确认目标网站、用途、序列范围（承接 RG-P0-01 consent 语义，扩展到一切外发）。

### 4.2 询问的时机（非常规，必须强制询问，不得静默执行）
以下"非常规操作"在执行前必须暂停并询问用户：
1. 约束放宽：滑动引物边界、放宽 Tm 窗口、放宽 GC 范围、放宽产物长度；
2. 降级路径：primer3 不可用→热力学近似、模型不可用→unavailable、离线→未校验；
3. "无解"判定：任何报告"无法设计"的输出，必须附替代建议并询问是否采纳；
4. 任何写入外部环境的行为（网络请求、浏览器打开、文件写入包外位置）。

### 4.3 明确告知（每个输出必须携带）
- 使用的后端与版本（如 `primer3_core 2.6.1` / `thermodynamic-fallback` / `NOT Primer3`）；
- 使用的参数窗口与来源条目编号（指向 §7 参数来源文件）；
- 降级/放宽标记（`primer3_retry_note`、`boundary_offset`、`experimental_backend` 等）；
- 物种适用性警告（Azimuth/DeepCpf1 未验证酵母等）。

### 4.4 操作透明可见
- 运行报告/日志记录每个操作：后端、参数、输入序列 SHA、重试路径、产出文件；
- AI 在对话中展示关键操作摘要（做了什么、为什么、结果如何），不隐藏失败与重试。

### 4.5 实现要求
- 询问机制以结构化交互接口实现（CLI 交互提示 + 报告中的"待确认"节 + 可编程 API 回调），测试覆盖"未确认不执行"与"确认后执行"两条路径。

## 5. 真实场景测试要求（论文来源，本迭代必须执行）

### 5.1 场景来源要求
- 全部场景**必须来自权威论文/官方文档**，禁止自造"看起来合理"的虚构序列充当验证；
- 每类场景标注出处（论文标题、DOI、URL、检索日期）；
- 允许使用论文附件/补充材料中的真实载体序列（注明 accession 或来源质粒）。

### 5.2 覆盖面与数量（"极多"的具体化）
| 场景类别 | 最低数量 | 来源示例 |
|---|---|---|
| 多片段 Gibson 组装 | ≥3 | Gibson 2009, Nat Methods, 10.1038/nmeth.1318 |
| Golden Gate 模块化 | ≥3 | Engler 2008, PLoS One, 10.1371/journal.pone.0003647 |
| 重叠延伸（SOE）/overlap 融合 | ≥3 | 论文案例 + IDT 指南 |
| 高 GC / AT-rich 模板 PCR | ≥5 | NEB/Takara 官方 protocol 案例 |
| 长片段 PCR（>5kb） | ≥3 | Takara PrimeSTAR GXL / NEB Q5 长片段方案 |
| 引物设计失败重试链（含边界/尾巴/GC 端部） | ≥10 | 本迭代 §3 的 A/B/C 组 + 论文失败案例 |
| 酶切连接/位点唯一性 | ≥3 | NEBcutter 案例 + 论文 |
| 真实载体全流程（骨架+供体双质粒） | ≥5 | Addgene/NCBI 公开质粒（注明 accession） |

### 5.3 验证标准
- 每场景以论文给出的结果（片段数、产物长度、引物可行性、组装成功与否）为**真值**，与 skill 输出对比；
- 差异必须分析并记录（环境差异 vs 实现缺陷）；
- 场景套件纳入 CI（真实后端门控），归档结果文件。

## 6. 供人阅读的结果报告（本迭代交付物之一）

### 6.1 定位
- **供人阅读**（开发者、审阅者、潜在用户），非机器日志；
- 强调可读性：分节、图表化、术语解释、结论明确、附执行摘要。

### 6.2 每个场景必须包含
| 字段 | 说明 |
|---|---|
| 出处 | 论文标题、作者、期刊、DOI、URL、检索日期 |
| 具体描述 | 场景要解决什么问题、为什么是典型场景、关键序列特征（GC%、长度、结构） |
| 如何使用 skill 解决 | 操作步骤：输入文件、命令/API、参数选择、询问与确认过程 |
| 过程中的产物 | 中间文件、每次调用的后端与参数、重试路径、最终输出（引物/方案/报告）、关键日志片段 |

### 6.3 报告结构（建议）
1. 执行摘要（一句话结论 + 总体通过率）；
2. 场景总览表（出处/类别/结果/通过与否）；
3. 每场景详情（§6.2 字段）；
4. 差异与缺陷清单（含与审查任务的映射）；
5. 附录：全部序列与输出文件索引。
- 命名建议：`reports/scenario-validation-human-report.md`（或 .html），与机器可读的 `scenario-results.json` 并存。

## 7. 默认生物学参数来源汇总文件（本迭代交付物之二）

### 7.1 文件
- `references/biological-parameters-sources.md`（人读）+ `references/biological-parameters-sources.json`（机读，可选）。
- 目的：**所有默认生物学参数单一来源可查**；AI 需要 PCR 体系/酶选择等参数时，依据此文件去对应数据库/网站提取拟合，**禁止凭记忆**。

### 7.2 必须覆盖的参数族（启动清单，需全量清点）
| 参数族 | 示例条目 | 来源类型 |
|---|---|---|
| Tm 计算 | Wallace 1979（2×(A+T)+4×(G+C)）；SantaLucia 1998 最近邻模型；Primer3 默认盐 50mM Na+/1.5mM Mg | 文献 + Primer3 文档 |
| 引物质量 | 长度范围、GC 20-80%、3' GC clamp、发夹/二聚体阈值 | Primer3 默认参数 |
| PCR 体系 | 退火温度策略、延伸时间 20-30s/kb、buffer/添加剂（DMSO/甜菜碱/GC Enhancer） | NEB Tm Calculator、NEB 酶选择指南、Takara 文档 |
| 组装参数 | overlap 15-40bp（IDT）；Gibson ≤4-5 段（Gibson 2009）；Golden Gate ≤8 段（Engler 2008） | IDT / 论文 |
| 酶切 | 保护碱基表、酶切位点上下文、NEBcutter | NEB |
| on-target/off-target | Azimuth（Doench 2016, 10.1038/nbt.3437）；DeepCpf1（Kim 2018, 10.1038/nbt.4061）；Cas-OFFinder 版本与 bulge 语义 | 论文 + 官方仓库 |
| 可行性规则 | M2 规则表全部条目（§v0.9 Spec）| 逐条标注 |

### 7.3 每条记录字段
`参数名 | 默认值 | 来源（文献/数据库/URL）| 版本 | 检索日期 | 备注/适用条件`

### 7.4 审计要求
- 每个默认参数必须有来源条目；无来源的参数不得作为默认值输出（沿用"不编造"原则）；
- 该文件本身纳入 REVIEWER-GUIDE 证据地图，审查时抽查参数↔来源↔代码引用一致性。
