# v1.0.3：真实任务修复与下一轮测试

2026年10月3日。**这一版修复了真实使用中可复现的程序问题，尚未证明九题都能由宿主独立完成。**

## 用户会看到哪些变化

| 原问题 | 本版处理 |
|---|---|
| 直接PCR入口不能处理带接头引物，GB扩展名却写出FASTA | 使用现有Core模拟真实PCR，输出正确的GB/DNA及源引物副本 |
| 拼出目标序列就算完成制备 | Recipe导出前重算实际模板和最终引物，不一致则停止 |
| 用户要求在选路线后被省略 | 保留原目标；允许引用原源feature核验。要求PAM破坏时可显式强制检查 |
| mNeonGreen被误识别为抗性 | 检查完整标记名称，不再用短子串误判 |
| 引物坐标不知道指哪个文件 | 下单表写明对应源副本和坐标体系 |
| 同目录重试失败后还留着上一轮成功结果JSON | 新尝试开始时移除上一轮当前回执；保留候选诊断，但不把旧回执当新成功 |
| QC引物只按Tm排名，忽略强发夹 | 使用真实Primer3筛除发夹和自二聚体，检查最终PCR引物对 |
| 宿主为查参数反复读源码 | 新增`python scripts/describe_tools.py 名称`，直接显示实际接口 |

原文件和失败结果保留。复杂源注释仍需依据真实用途校订副本，不自动改DNA、改遗传密码表或放宽验收。

## 怎样确认有效

本轮同时做程序反例、原失败回放和一次新自然请求试用。它们回答不同问题：代码是否修复、旧失败是否可正确处理、宿主能否自行选路。

新试用用四份真实源质粒制备一份URA3低拷贝红荧光表达质粒。检查者未使用执行AI的核查脚本：重新计算6步PCR、4个30 bp接头、26条引物坐标和4组亲本对照，最终6429 bp序列一致。桌面SnapGene实际回读正式GB和带QC引物DNA，序列、拓扑、注释均保留。

试用使用的是本轮开发快照；随后发现并修复默认QC筛选缺口。最终包另做接口回归。**一次强模型试用不是DeepSeek旧版/新版对照，也不是正式成功率。**原九题还需要在相同宿主、预算和帮助条件下重测。

完整测试结果、命令与未决项见[开发记录](../plans/workflow-host-readiness-v1.0.3.md)。下一轮按[评分规则](../../question-bank/scoring-v0.1.md)检查目标、制备、文件、验证与结论，不能用正确最终序列抵消错误引物。
