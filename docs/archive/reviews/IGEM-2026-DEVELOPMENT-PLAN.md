# DNA 构建关键缺陷修复计划

版本：3.0，2026-09-06。范围：现有代码修复与真实质粒交付。

## 给项目负责人的简要说明

本轮解决四件事：空报告不能放行，复杂特征不能提取错，酶切查询不能把黏性末端报成平端，多步构建不能丢注释。同时在现有验证入口检查用户要求保留和排除的组件。

完成标准是实际构建出的文件正确。单测用于防止缺陷复发，测试数量不代表可发布程度。保留[原审计报告](IGEM-2026-SOFTWARE-AND-SAFETY-AUDIT.md)作为问题来源；本轮完成不等于其中全部缺陷均已关闭。

## 最小修改范围

1. **准入门禁**：修改 `core/runtime_gate.py`。拒绝空、缺项、失败和未完成的报告；针对实际候选文件重新检查，防止裸序列报告遗漏 CDS 后仍放行。
2. **特征提取**：修改 `core/tools/feature_ops.py`，使用 `feature.extract(record.seq)`。现有 CDS 检查使用同样的原生提取方式。保留分段顺序及链方向。
3. **酶切几何**：在 `core/tools/restriction.py` 内统一查询与 digest 的切点、末端类型和突出序列。覆盖跨原点切点；在线性片段外的切点不能作为已发生的切割。
4. **注释传递**：复用现有 `SeqRecord` 和特征序列化函数，修复 Pipeline、PCR、组装工具、Recipe 和导出之间的注释丢失。保留插入片段与骨架特征的正确坐标、方向、分段和 qualifiers。仅修改实际传递链。
5. **组件检查**：在 `composite_pipeline.py` 和 `runtime_validate.py` 内检查任务中的 `expected_components`、`forbidden_components`，兼容已有 `product.required_components` 和 `product.forbidden_components`。直接比对实际产物及原始来源，不从计划 hash 推断达标。

不新增 `goal_validation.py`、规则引擎或验证状态体系。不引入 W/R/A 验收矩阵、大型 Benchmark、新产品模块或全仓重构。

## 对应单测

- 空凭据、伪造通过摘要和带内部终止密码子的实际候选文件被拦截。
- 正负链 join 与跨原点特征提取正确。
- EcoRI、3′ 黏性末端、平端和 Type IIS 的查询与 digest 一致。
- 方向错误、目标缺失和删掉注释后的禁用组件仍能被检出。
- 注释经过多步构建和 `.gb` / `.dna` 导出后，序列、坐标、方向和必要 qualifiers 保留。

已有相关测试需回归。只为实际失败增加测试，不按数量扩充用例。

## 真实交付检查

使用仓库中的真实 pDONR201 和 EmGFP 来源文件。移除原替换区，扩增 EmGFP，再进行重叠组装。输出 2777 bp 环状质粒。

核对完整序列及两端接头；确认 EmGFP、KanR、复制起点和两个终止子存在，ccdB、CmR 已移除。原本被替换区中的特征移除属于预期结果。

保留任务 JSON、来源路径、产物 `.gb` / `.dna` 及简短实测结果。用桌面 SnapGene 打开最终 `.dna`，检查地图与特征，通过官方导出再次核对序列和酶切位点。若桌面操作或授权受阻，明确标为未完成，不能以内置解析器通过替代桌面验收。

## 组件输入约定

组件可用明确序列声明，例如 `{"name":"EmGFP","expected_sequence":"ACGT...","strand":1}`。`strand=1/-1` 指该序列或其反向互补在产物参考链上的方向；省略时允许任一方向。禁用组件检查两个方向，环状产物检查跨原点匹配。

按名称声明时，从任务原始来源中解析同名特征并提取序列。名称无法解析、存在不同候选序列或序列含不明确碱基时，报告无法核验，不默认通过。序列存在只说明构建内容符合要求，不证明表达成功或湿实验有效。
