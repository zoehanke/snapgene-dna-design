# GFP 片段修订：为什么最后多了 3 个碱基？

历史静态稿 r1，2026-09-11；2026-09-12 已取消主要 UX 案例资格。仅作为 GFP +3 bp 工程回归的背景记录保留，以下试读流程不再执行。Reader Demo 另见 新案例稿（原稿曾公开，现已移出当前树并完整私有备份；历史仍可见）。

## 设计目标与当前结果

从完整的 pBP-eGFP 质粒扩增一个 GFP 片段，再将片段末端延长 3 个碱基，比较两版设计。

**结果：第二版得到 717 bp 的线性片段，已生成 construct.dna。两版程序检查均通过。仍需确认：这段片段是否适合后续酵母构建，现有记录没有表达实验依据。**

这是使用真实模板和程序产物的软件演示。目标与选择说明由演示作者预先提交，不能当作真实用户指令或 AI 当时的对话。

## 设计怎样形成

### 1. 选择完整质粒作为来源

记录中的选择是：使用完整 pBP-eGFP，通过 PCR 工具制备片段。

演示作者给出的理由是：从实际模板计算扩增产物，并保留来源注释。现有源文件提供了 GFP 的位置注释；它能帮助定位片段，但不能证明后续表达效果。

### 2. 先制备第一版

第一版选择区间 `[6, 720)`，得到 714 bp 线性片段。该区间是演示中指定的对照边界，没有记录“它比其他边界更好”的证据。

程序完成了产物文件、计算过程和任务目标三项检查，结果均通过。这些是程序结果，不是新的设计决定。

### 3. 修改末端和预期用途

演示作者将末端从 720 改成 723，起点不变，片段增加 3 bp。同时，把记录中的预期用途改为后续酵母构建的供体。

两种变化需要分别看：末端变化影响这次实际生成的序列；用途变化提出了新的适用性问题。把用途写成“酵母供体”，不等于程序已经验证酵母表达。

### 4. 根据新边界重新生成产物

程序沿用同一完整模板，重新计算扩增与检查。第二版为 717 bp 线性片段，三项程序检查再次通过。

第一版的通过记录仍属于第一版。第二版已有自己的检查结果；这不自动处理旧证据对新用途是否适用的问题。

### 5. 交付第二版文件

最终文件是第二版的 **construct.dna**，同时提供 GenBank、FASTA 和引物订购表。不能因为两版文件名相同就混用；实际文件分别存放在 `end-720-on` 与 `end-723-on` 目录。

## 点开“修改末端”时看到的详情

**改了什么：** 起点仍为 6，末端从 720 改为 723。坐标为 0-based、右端不含，区间长度从 714 bp 变为 717 bp。

**原说明：** 演示作者记录“增加末端 3 bp，沿用源模板，交由原 PCR 工具重新设计并验证”。这是一条已提交说明，无法据此证明存在同内容的原始用户或 AI 对话。

**主要依据：** 源文件提供位置注释；本例没有记录支持“延长后功能更好”的论文或实验。

**实际检查：** 新版本的文件、计算和目标检查通过。检查范围不包括酵母表达、培养表现或生物安全。

**受影响的旧记录：** 第一版验证仍真实，但对应旧边界；新用途还需要检查原有证据的适用条件。不能只看到旧 PASS 就沿用全部判断。

**对应产物：** 第二版 `end-723-on/authoritative/construct.dna`，717 bp。

## 试读方法与停止条件

由 **2 名未参与本案例的团队成员** 分别试读。先看正文，计时后回答，主持人不提前解释。两人都须达到以下条件才进入 HTML 实现；未达标先修改稿件。该样本用于本轮开发判断，不代表普遍用户效率。

1. **5 秒：** 说出设计目标，以及当前最需要关注的未解决问题。
2. **15 秒：** 说出来源选择、边界修订和程序检查的顺序，并指出本例不能将演示作者归为真实用户或 AI。
3. **30 秒：** 找到修改理由、依据限制、第二版程序检查及对应产物；区分“程序通过”和“后续用途有证据”。
4. **不计时补查：** 阅读来源标签对照，确认 Observed 会保留用户理由，事后解释不会冒充当时说明。
