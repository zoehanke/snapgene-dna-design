## D01：先修确定的工具错误

修改`core/tools/assembly.py::simulate_overlap_assembly`的最长重叠搜索，消除未声明的60 nt截断。先查现有可复用搜索实现；没有时采用有明确复杂度的匹配方法，避免取消上限后变成长序列平方级逐串比较。保持物理线性输入、环状闭合、最小重叠和源注释变换要求。

验收包括独立40/60/61/80及更长重叠、低于最小值、无匹配、重复序列、完整包含或完全重叠、线性/环状闭合。完整包含等边界先明确工具语义，不直接按最长字符串剪接宣称可制备。预期由独立构造关系确定；不使用实现本身生成答案。

公开API和实际Recipe/Pipeline调用均检查真实序列、拓扑和注释。只修该缺陷不会自动纠正第2题的产物与注释，不能就此报告整题通过。

## D02：把正确调用做成最短路径

当前原子工具由`ToolSpec.execute`检查输入并返回ToolResult；Recipe返回RecipeResult，现有Pipeline只接受前者。保持原子工具的严格契约，在Recipe边界增加局部适配，保留products、检查subject、角色、完整性、引物、准备、协议和引用。QC subject不伪装成新构建产物，零/多产物不得默认挑第一个。

从`run_pipeline_steps`提取单步调用责任，供现有Pipeline循环和直接Python调用共同使用。CLI增加薄的单步入口，文件读取和JSON编码仍使用现有resolver/wire。原子与Recipe参数定义从真实签名及现有声明校对，不再增加第二份手写接口表；`describe_tools.py`与执行入口共享这份定义。

一步执行记录实际方法、规范化参数、输入版本、产物版本与选择、检查和错误。完整分子保留，Python不反复转JSON；同一运行的文件边界按版本保存一次材料。失败返回具体步骤、原CoreError和已完成前缀，不把失败伪装成成功结果。

宿主可执行一步、看结果、再决定下一步。续用已完成结果要核对原输入、参数与实现/后端条件；本轮只需进程内或本地文件继续，无全局状态库和分布式恢复平台。

验收覆盖Recipe→原子、原子→Recipe、Recipe→QC、分析输出、显式多产物选择；未知方法、错参数、缺前置产物、步骤失败均有可处理的结构化结果。成熟方法内部动态搜索照常工作。

## D03：实际材料交接与选择

分子摘要来自真实Molecule，显示产物编号、长度、拓扑、自由末端、来源版本和主要保留特征，附完整数据位置。全部酶切与单片段释放的说明区分清楚；多产物按显式编号或可验证、无歧义的条件选择，名称相似和默认首项不能替代选择依据。

后续步骤直接消费选定Molecule。源文件只读，序列变化与注释坐标变化由同一次领域变换完成；保留负链、复合位置、环形起点、部分注释及原始身份。不要在宿主脚本里重新复制字符串再补坐标。

主要落点为digest定义/返回摘要、`core/tools/result.py`、`core/models/molecule.py`及调用示例。已有变换不自动重写，先用真实跨工具记录证明哪里丢失，再修对应生产者/调用者。

验收包含不同长度/角色的多个产物、含同名重复元件的歧义、源注释复合位置与负链；核对变换前后源文件未变。第2题材料选择作为原失败回归，独立输入验证边界，不内置该题选择。

## D04：自主流程进入共同核查

提取`runtime_validate.py`中可独立调用的文件、CDS、目标元件和注释比较职责；保留ConstructionTask现有调用。新增候选核查入口接收原要求、源材料、实际完成步骤、候选分子/文件和最终引物，不要求先套某一固定task_kind或预填整条路线。

核查四个范围：

| 范围 | 要证明什么 |
|---|---|
| sequence_model | 原材料和实际操作可重建候选；序列、拓扑、末端及源注释对应 |
| preparation_model | 从原模板、最终完整寡核苷酸或实际酶切重放，逐步得到真实中间体和最终材料 |
| file | 写出/回读一致，注释和所有必需文件正确，文件对应当前对象 |
| user_goal | 可检查的必需/禁止项满足；语义覆盖缺口和需要本人判断的部分明确保留 |

源注释比较仍从原输入和实际变换重建预期，不使用候选自己的注释作为答案。复用`_preparation_check`的来源追踪，但外部导入的steps/checks必须重放，不能凭operation名、source_refs或PASSED字样认可。逐PCR重放还必须接到后续组装；最终比较允许经过核对的环形起点变化，不接受近似序列替代精确要求。

自定义算法输出可以导入并核查文件、元件及有依据的变换。没有重放依据的范围为INCOMPLETE，不强制重写成静态Pipeline，不因Python执行完毕或Schema合法宣布正确。开发者独立正反例另证明算法边界；运行时同算法重放只证明一致性。

验收至少包含：引物均结合但组装结果不符、改一条最终引物、注释错位、丢复合位置、错误产物选择、伪造来源/checks、源材料修改、无证据自定义方法。合法原子组合、自定义组织的可重放流程及成熟方法都应得到对应范围的真实结果。

## r2实施事实与修订原因

始于指定开发分支3bb2e7d，fetch核对远端同版本，保留原无关未提交状态。只在Skill内部提取现有步骤、核查、准备/文件及交付职责，不引入新依赖、DSL、服务/状态库。Core契约、架构和Skill公开使用说明同步更新。

原长重叠反例先失败再修复。完全重叠没有独立贡献，工具不把吞并输入当作已证明可制备；这是显式工具边界，调用者可选其他支持方法。准备Writer改用as_molecule保留Wire的物理状态；逆PCR新增真实环化和受核对的起点变换，不再仅改拓扑。QuikChange保存完整产物Wire及真实窗口证据。PCR、QC和合成用途不会互相替代。

首轮1031项诊断有14失败、6错误、8跳过，保留日志。发现真实接口/表示问题后逐项修复，不将其记为通过。旧sanity-only提升测试保留原输入并新增明确拒绝断言；其原子/碰撞/桌面子责任在原物理promoter上继续验证，完整公共反应交付另由独立PCR链验收。这是新的更强执行凭据要求，不是放宽阈值。新测试首次使用未指定方向misc feature却预期GenBank无损不成立，保留同一None方向反例并确认file失败；正例明确声明方向，不能把它计作原输入成功。

code-review两轴独立探针确认并修复：历史续用、裸序列来源表示、逐位信息、引物角色、指定中间体、假扩展名、订单/说明/配套记录及正式native哈希。Guide比较对两侧对称规范化引物；原始文件先核对指纹再规范化，继续拒绝实际文件编辑。共用I/O移入Core，原CLI保留使用中的兼容入口。

原T2仅依据原请求与七源材料，开发者显式选择全部BsaI digest产物后纯化/连接，不读取答案、不改源，5283 bp正式交付，7个实际中间体及18个必需特征经独立原输入推导核对，3条引物均QC，22个文件哈希匹配，colony PCR独立为473 bp。首次源码变化导致条件失配被正确拦截并保留run-01，稳定后run-02成功。属于开发者选路/补参回放，不能替代DSH原宿主自然重测或陌生评测。
