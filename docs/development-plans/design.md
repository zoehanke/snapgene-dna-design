# Evidence Trace：人类阅读与界面规范

r9，2026-09-19。当前阅读规则的唯一来源；取代旧固定六栏与单 Decision 环形布局。旧实现见 Git 历史及 [Phase 3 记录](safety-phase-3-change-impact-v0.3.md)。本规范面向后续固定 renderer，当前 HTML 及新过程/编排接口尚未重构。

[安全 spec](../../specs/safety-module.md) 定义事实边界，[当前计划](safety-phase-3-readability-v0.3.1.md) 定义实施与验收，[Reader Demo](safety-phase-3-reading-draft.md) 提供具体样稿。实现阅读结构前还须读 [标准空白框架](evidence-trace-reader-template.md)：本文件定义阅读规则，框架定义可选结构，案例检验填入后的效果。结构或显示规则变化时同步相应文档，不重复整段规范；完整框架不代表栏目必须全部出现。此文件不作为宿主运行时生成网页的提示词。

数据接口见 [数据层到阅读层映射](../../references/evidence-trace-reader-mapping.md)。第四步已提供统一 reader 投影，原记录留在详情引用中；第五步才切换 HTML。关系必须区分声明依据、修订、调用阶段、材料引用和实际生成，不能把普通排序画成因果线。

## 为谁服务

目标输入见[三层 r2](safety-phase-3-three-layer-design-v0.3.1.md)：数据层已形成完整 design_process，另有 report_plan 指定阅读顺序、摘要、短标签和展开安排。报告不能首次发明研究逻辑。AI／人确实参与编排，可与数据组织同次输出；固定渲染、导出和交互不再次调用模型。

每个摘要、图中步骤和重要解释须能回查完整过程及原记录。初始收起不删除数据；未归类材料仍可查。编排绑定确切组织版本，新增事实导致旧组织陈旧时明确显示范围，不能把旧摘要套用到新产物。程序固定保留文件角色、原检查状态与影响当前判断的未解决问题。

默认页面服务于未参与设计、具备基础生物学知识的研究者。让他不展开审计信息也能说明：用户想做什么，谁做了哪些选择，依据是什么，程序查了什么，最后得到什么。

理解优先于默认展示完整。每条信息先问“帮助理解哪个研究问题或决定”；每个栏目先问“本任务是否真实存在”；每条关系先问“记录是否支持”。不满足就不默认展示，但保留底层事实。

## 上下文与主链

开头用短正文交代研究/任务背景、为何做设计、用户当前要求、AI 和程序各自参与什么以及 Trace 的用途。小任务可以合为一段，不要求四张卡片或四个栏目。缺背景不能从参数猜出项目故事。

主结构是 **任务背景 → 设计形成过程 → 本次结果**。主链只放推动选择、改变方向、解释关键材料或交付所必需的事件，不是完整运行日志。

| 阅读步骤 | 表达方式 |
|---|---|
| 要求 | 用户目标、约束、明确修改；原话与宿主摘要区分 |
| 选择 | 用户/AI/未知选择者；遵从明确要求不包装成 AI 自主取舍 |
| 程序结果 | 区分发现、计算和正式检查，说明实际范围 |
| 产物 | 关键中间体、候选、最终文件；同名文件带变体/版本语境 |

步骤标题统一采用 **`编号 · 类型前缀｜具体内容`**。前缀固定，正文自由：要求用“用户要求”；选择用“用户选择 / AI 选择 / 选择者未记录”；检查、发现和计算统一用“程序结果”；文件用“中间产物 / 最终产物”。例如“01 · 用户要求｜确定比较组”“02 · 程序结果｜核对来源”“03 · AI 选择｜采用顺序制备”。不要把某类前缀省略并混入标题正文。用户明确指定的约束归“要求”，真实取舍才归“选择”；仅有人工/文献核对而没有程序依据时，不冒标“程序结果”，应保留为有来源的事实旁支。

静态 Markdown 样稿只用标准标题、段落、引用和链接。详细内容放可跳转的附录，不嵌入 HTML 折叠标签；未来 HTML 的折叠由固定 renderer 实现。类型标签和参与者需要一致，句子不必套固定话术，也不要求每种类型都出现。

用户确认归于对应要求/选择；待办附着于相关步骤。四类是阅读组件，不扩展底层科学节点体系。例行读取、每次工具调用、参数碎片、ID、哈希和原始 JSON 下沉详细记录。

## 决策旁支

主链步骤写“谁做了什么”；理由、依据、限制附着在相关选择旁，不各自挤成一串主链节点。

- 理由：选择者实际留下的公开说明。Document 默认可露出一句；缺少就不补造。
- 依据：相关用户约束、输入事实、程序结果、论文或数据库。多条细节折叠，保留其具体支持方面。
- 限制：该依据不能推出什么；重要冲突/限制默认简短可见，详细条件折叠。

替代方案和下一步行动只在已记录且有用时出现。Mind Map 默认折叠理由/依据旁支，选中后展开；不能把折叠变成隐藏关键失败或冲突。

来源用“用户说明”“AI 当时说明”“未记录原始说明”“事后辅助解释”表达。旧来源不充分时写来源未确认。机器字段仍在详情，不要求研究者理解 actor 或 mode_at_capture。

## 条件性内容

| 内容 | 何时显示 |
|---|---|
| 用户修改/否决/确认 | 有明确用户来源及对应对象 |
| AI 理由 | 有真实说明；Full 关键选择缺说明时提示其具体缺口，Observed 不强求额外说明 |
| 证据/限制 | 存在对应材料或影响理解的证据边界，不强制论文链 |
| Change Impact | 有变化及关联影响，挂到实际受影响步骤 |
| 待复核 | 用户目标未被回答，或有具体证据缺口、未处理影响、人工判断项；写清对象与行动 |
| 待实验回答 | 当前用户目标涉及计算无法回答的科学/性能判断 |

简单任务可以结束在已交付文件，不生成空栏目或泛泛的实验担忧。缺失已要求的检查、失败及重要冲突必须保留；“未要求”不改写成“检查失败”。同一次程序检查按实际作用范围展示一次，不复制到所有 Decision 下暗示全面证明。

## 三种视图与顺序

Document 纵向阅读同一过程；Mind Map 图形化看整体与分支；Split 左侧完整图，右侧选中步骤详情。三者共用数据、步骤选择和展开状态；用户修改或程序发现也能选中。Review 只看当前具体待办，无待办时不占主要入口。

以可证实的执行、材料和修订关系为骨架，研究逻辑作分组，记录顺序作补充。参数可能在工具返回后才被观察，追加时间不等于选择发生时间。并行变体并列；只有明确关系才标“导致/因此”，普通先后不能冒充因果。晚补说明挂回原步骤并保留补录身份。

详细来源、定位、版本、内部 ID、哈希、原事件、完整 Artifact Trace、Advanced Graph 和 Audit Log 统一收在“查看详细记录”。主线保留结果身份和可打开的产物入口。

## 语言与视觉

每节回答一个与当前任务有关的问题。专业词首次出现解释其意义，而不只展开缩写。使用已有文本和受证据约束的固定表达；renderer 不凭突变名称、参数或论文题目自动生成科学理由。

Reader Demo 开头一次说明：“它记录关键选择及依据供人复核，不作安全裁决，也不展示 AI 隐藏思维。”模拟对话与回放结果一次清楚标记，内部案例来源放详情，必要的未执行状态不能隐藏。

冷灰白、细线、清晰版心与留白；正文约 15–16px、行距约 1.7。等宽字体仅用于确有必要的标识/坐标。用来源文字配少量语义色，不依靠颜色区分角色。不设 KPI 卡片墙、渐变或装饰性网络。键盘、窄屏、离线与 reduced motion 支持保留。

## 正反例

- 不写“论文支持先做单突变再做双突变”。写“论文支持研究该候选；顺序制备是为保留比较材料作出的路线选择”，并分别提供依据。
- 不写孤立的“Validation PASS”。写“程序检查到编码区无提前终止且保留末端终止；独立目标检查未请求”。必须取自实际结果，不能把整质粒摘要误用于某个 CDS。
- 不写每个任务都“还不知道会不会表达”。仅当用户目标涉及表达表现时列为待实验问题；仅交付构建的任务可在准确说明检查范围后结束。

## 验收

先确认 Reader Demo 场景，再用静态稿做真人理解测试，通过后才重构 renderer。案例认可、静态理解、浏览器可达性、真实页面理解分别记录。无反馈不算通过。

不展开详细记录，读者应能回答任务目标、用户/AI 取舍、具体依据范围、程序实际检查和产物身份。问理解问题，不用好看或字段齐全代替。5/15/30 秒用于记录定位效率，理解错误必须修稿；不能用压缩文字制造漂亮数字。两名试读者的原回答与耗时保存在计划的验收记录中，不另建 benchmark 系统。
