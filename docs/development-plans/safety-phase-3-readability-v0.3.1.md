## 1. 给项目负责人的简要解释

这轮解决“记录很多，但读者仍要自己拼出设计过程”。默认页面应讲清：目标是什么，谁选择或修改了什么，为什么，依据和限制是什么，程序检查了什么，最后得到哪个文件。

先整理采集来源和一份真实案例的理想阅读稿，团队能读懂后再实现页面。保留现有事件、证据关系和 Change Impact，增加一个确定性的阅读整理层；不重造生物安全引擎，也不靠 LLM 临时编故事填满页面。

交付是一套 Skill 中的 Off / Observed / Full，加上可顺读的决策链、完整设计导图和可行动的复核队列。Full 只是多记录关键选择的简短公开说明，不代表安全结论或隐藏思维记录。

## 2. 现状与替代关系

已检查 `runtime.py`、`recorder.py`、`coverage.py`、`chain.py`、`render.py` 及现有计划/spec：

| 当前实现事实 | 本轮处理 |
|---|---|
| CLI 以 `--trace`、目录/输入参数启用；`normal/strict` 控制故障处理 | 增加全局采集级别，和故障策略明确分开 |
| 事件已有 actor，但 bundle 导入默认标为 host-assistant | 区分记录提交者和实际选择者，补充可核查的来源引用；不直接把 actor 当科学决策者 |
| coverage 把明确目标匹配且存在 rationale 合并为 explained | 分开“观察到选择”“已知谁选择”“是否有原始说明”，不把 Observed 的预期缺省当程序故障 |
| chain_views 按 run/Decision 整理底层关系，页面仍直接面对大量记录类型 | 在现有派生过程加入 Researcher Projection，主页面只读此层 |
| 导图固定以一个 Decision 为中心，章节只围绕其证据展开 | 默认改为完整设计过程，单步详情按需展开；保留三模式共享状态 |
| Change 对象、保守影响判断和原产物绑定已实现 | 复用计算与事件语义，改写面向人的表达，不翻修影响引擎 |

前序回归和 CI 证明当时的工程行为，不证明阅读有效。本轮保留旧计划与旧日志，标明被替代的 UI，不把历史“工程完成”改写成“用户验收通过”。

实施时同步两个 spec 和 design.md：明确 Design Decision Trace、全局级别、说明来源、完整主链导图。现有“单 Decision 环形布局”和“一律不允许事后解释”的规则分别替换为完整逻辑导图、允许独立标记的事后辅助解释；禁止伪造原始 rationale 的原则保留。本次计划写入不宣称这些能力已经实现。

## 3. 采集契约

### 一个全局级别，一套 Skill

| 级别 | 记录内容 | 模型负担与页面表达 |
|---|---|---|
| Off | 不建立新 Trace，不删除已有记录 | 不安排 Trace 专用解释；旧记录仍可只读打开 |
| Observed | 工具实际收到的输入、已解析选择、真实结果/验证/产物及变化；有明确输入来源时保留用户指定或修改 | 不要求额外 rationale，不自动调用 observer；没有说明时解释是模式边界 |
| Full | Observed 全部内容，加关键选择发生时留下的公开说明 | 通常 1–2 句；漏记保留缺口，不能为了达标自动补成原始说明 |

- 开发默认 Full；正式产品默认值留待试用决定。只设一处 `trace_level = off | observed | full`，不做 conversation/session 注册或覆盖机制。
- 先核对配置与所有公开入口，确定一个全局设置的保存位置及读取方式。现有参数的兼容语义在实现前写入使用说明，避免 `--trace-dir` 在 Off 下悄悄重新启用记录。
- `normal/strict` 继续只表示 Trace 故障策略，不对应 Observed/Full。normal 故障不拖死 DNA；本轮不改变 Core 验证和交付规则。
- 新事件保存 `mode_at_capture`，一轮执行使用启动时读取的级别，后续设置变化不重标历史。旧记录缺此字段显示“采集模式未记录”，不能推断成 Full。
- Observed 接近零的是额外模型 token，不是零计算/存储成本。验收记录额外调用与文本量，不能以“没有内置模型 API”代替完整宿主工作流核查。

### 谁选择、谁记录、何时解释

- 用户选择、AI 选择、程序结果、外部证据分别呈现。程序输出和最终文件不是 Decision；最终参数不能反推出是谁作出的选择。
- 可自动记录的是程序可见的数据。用户指令、否决或确认需宿主提交真实来源片段/引用；未收到则标“选择来源未记录”。不抓取完整聊天，也不声称记录了工具不可见的对话。
- 沿用 actor 记录提交者；按需补充选择者、来源引用、说明类型及其记录时间。来源是可审查声明，不是身份认证；时间接近也不能单独证明“AI 当时说明”。
- 前台至少区分：**用户说明 / AI 当时说明 / 仅记录选择，没有原始说明 / 事后辅助解释**。旧说明来源不充分时保持未确认，不自动贴“当时”标签。
- 事后辅助解释是独立追加记录，引用被解释的选择、已有事实和生成时间；不覆盖 rationale、不抹掉原始缺口、不提高原始说明覆盖率，也不能冒充 Validation。
- 本轮提供事后解释记录/展示入口，不新增常驻 observer、后台模型服务或自动补全流程。有人或宿主明确提供补充时才记录。

## 4. Researcher Projection：薄的确定性阅读层

保留 `events.jsonl → graph/现有关系与影响 → 阅读投影 → HTML`。投影只组合、排序和转述已记录事实，不增加另一份事实源、规则引擎或新持久化数据库。

一份投影包含：设计目标、按记录顺序组织的关键步骤、选择者与说明来源、主要依据及限制、实际程序检查、修改前后及影响、最终产物、待复核事项。每个摘要保留底层记录/修订/运行引用，点开能回查。

记录顺序与因果关系分开：只有已有依赖/修订证据才称“因而调整”。晚补录说明不倒插成历史原话；工具输入不等于执行成功；同一选择的多条字段观察可聚合，但不能合并不同版本、不同选择者或不同证据限制。

| 默认阅读 | 点击展开 | 高级审计 |
|---|---|---|
| 目标、关键选择/修改、来源、短说明、主要依据/限制、检查范围与结果、待办、产物名称 | 原文献与定位、Statement、相关 Claim、各维适用性、替代方案（如已记录）、变化前后、详细检查、其他产物 | internal ID、revision、算法版本、原有哈希、原始事件、完整关系网络 |

主要依据按固定关系类别整理，支持、限制、冲突均可见。证据多时标明还有多少条可展开；不只挑支持证据，不把 source verified 写成“设计得到证明”。没有适用证据就直说未记录。

优先扩展现有 `chain.py` 派生接口；只有阅读逻辑确实需要隔离时新增一个小模块。Document、Mind Map、Split、Review Queue 共用投影，不各算一套关系或解释。

## 5. HTML 阅读方案

**首页是完整设计过程。** 顶部用自然语言写目标和当前具体待办；正文顺序为“用户目标 → 关键选择 → 用户修改（若有）→ 后续选择 → 程序检查 → 正式产物”。没有用户确认事件，不插入确认节点。操作日志不混入主线。

- **Document / 决策链**：一项选择一个短段落。先写“谁决定做什么”，再写“当时说明、主要依据、重要限制、实际检查、变化影响”。无内容的部分给明确原因，不展示 `rationale=null` 或成排空卡片。
- **Mind Map**：设计目标为根，关键步骤形成清晰主干，证据/限制挂在对应步骤旁。显示完整逻辑而非单节点圆环；默认聚合证据，展开分支不打断主干。只给真实关系连线，复杂交叉关系放高级视图。
- **Split**：左侧仍是完整过程图，右侧是选中步骤详情。切换三个模式保留步骤、证据分支与展开状态；对象可以是用户修改或程序结果，不再限定必须选中 Decision。
- **Review Queue**：按相关步骤聚合“需要检查什么、为什么、从哪里查”。Observed 缺 rationale 是信息边界，Full 漏记是记录缺口，两者不伪装成生物学失败。未知影响不隐藏，正常的“未要求验证”不生成错误待办。
- **Change Impact**：先显示“哪个条件从什么改成什么，以及哪些判断、证据或检查需要重看”。状态码和依赖路径下沉详情。只有明确依赖才写确定影响，可能/未知关系保留措辞；旧 PASS 不改成 FAIL。
- **高级信息**：统一收起 Advanced Graph、Audit Log、Raw Trace、完整 Artifact Trace。主线仍保留正式文件入口和最短追溯路径。

视觉沿用冷灰白、细线、清晰版心与留白，正文优先，少量颜色配文字区分用户/AI/程序/外部证据。默认以中文科研语言展示，名称、坐标和必要原文保留；ID 不作主标题。无需靠新增视觉库或装饰性动画解决阅读问题。

## 6. 实施顺序与修改落点

1. **整理数据与规范。** 建立上面的字段三级展示映射，核对实际入口、历史字段与缺口；同步两个 spec 和 design.md，明确本轮替代范围。暂停 Phase 4。
2. **完成级别和来源采集。** 在现有 wrapper、Recorder、CLI/宿主说明中实现全局级别、mode_at_capture、选择者与说明来源。将选择匹配与原始说明覆盖分开；不向 Handler 埋点。
3. **先做人能读懂的案例稿。** 使用已有完整模板 PCR 边界修订案例的真实记录，手工整理完整决策链、完整导图、单步展开、复核队列。缺少真实用户否决/确认就不补造；另用明确标注的角色演示检查该分支。此步不写页面代码。由未参与设计的团队成员试读，记录答题与卡住位置；未能理解则修改信息组织后再进入页面实现。
4. **实现阅读投影。** 保留原事件与链接，形成共享步骤列表、摘要和待办，测试来源、晚补录、旧数据和多条件证据不被混淆。
5. **先 Document，再完整 Mind Map。** 先保证能从头读懂，再做主干布局、分支展开和 Split 连续定位。最后整理 Review Queue、人话版影响、统一高级入口。
6. **真实工作流验证与交接。** 完成三档对照、故障隔离、浏览器与团队计时；更新计划实际结果、限制、两个 spec、design.md 和索引。验证后 commit/push 到指定分支，核对该提交 CI；没有用户阅读证据不能只报“验收完成”。

预计修改范围：`evidence_trace/` 的采集、派生和 renderer；`scripts/trace_design.py` 及三个现有运行入口必要的接线；`SKILL.md`、`references/evidence-trace.md`、相关测试与演示脚本。Core、planner、Handler、执行参数及 authoritative artifact 不在修改范围。

## 7. 验收以理解与事实一致为准

| 检查 | 通过依据 |
|---|---|
| 5 秒 | 未参与设计者能说出目标和当前主要待办 |
| 15 秒 | 能复述关键选择/修改，并分清用户、AI 和程序角色 |
| 30 秒 | 能找到一项 AI 选择的原始说明或准确说明其缺失，再找到依据、限制、实际检查和产物 |
| 三档采集 | Off 不新建 Trace；Observed 无额外解释任务；Full 保留观察骨架和简短公开说明；级别切换不重写历史 |
| 说明可信度 | 原始/事后来源不能混淆；晚补录不洗掉漏记；旧日志身份/模式未知仍如实可读 |
| 信息密度 | 多证据案例仍可沿主干阅读；冲突和条件限制不因聚合消失；无 Decision 的纯 Observed 运行也能显示实际过程 |
| 交互 | 三模式共享步骤和展开状态；来源、变化、检查、产物可达；键盘、窄屏和离线读取可用 |
| DNA 主线 | 相同固定输入分别运行 Off / Observed / Full，序列、拓扑、注释、引物、制备、Validation 语义及正式文件一致；Trace 故障按原 normal/strict 契约处理 |

复用前序真实模板、三条入口回归与多证据样例，补与新增契约直接相关的用例，不另造大型 Benchmark。记录团队试读的人数、答案、耗时和误解；人数与过线判定在试读前确定。自动截图/点击通过不能替代上述理解任务。工程和用户阅读验收分别记状态。

## 8. 前序交接与未决项

- **承接**：阅读负担、5/15/30 秒未实测、宿主采集负担、说明来源不清。本轮直接处理。
- **保留**：追加日志、原有版本/产物锚点、Source/Statement/Claim/Decision 分离、Applicability 限定与保守 Change Impact、normal 故障隔离。
- **已知限制继续公开**：只覆盖程序可见输入和明确提交的说明；结构化字段有限；来源核验不等于科学适用；单写入者、原产物路径、外部服务同意与许可要求不变。
- **待实施前确定**：单个全局配置位置、旧 CLI 激活参数的兼容规则、试读参与人数与判定方法。它们不扩展为会话管理或配置框架。
- **待正式发布决定**：默认采集级别及 Full 额外模型负担是否可接受；开发默认 Full 不等于发布默认 Full。
- **延期**：Phase 4 Assurance Case、Defeater、Mitigation、Conclusion Boundary、宏观框架、Safety Score、safe/unsafe、自动 observer 服务和多人协作。本轮不启动。
- **完成记录待填**：具体改动、真实运行/试读证据、失败与修正、遗留限制、提交及 CI。未获得团队试读时明确写“工程完成，阅读验收待完成”。
