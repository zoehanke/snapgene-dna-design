## 要解决的问题

单工具正确，不足以证明真实材料能连续经过提取、变换、反应、验证和文件交付。现有部分工具在字符串输入下正常，接收到Pipeline传递的完整记录后出现错误；注册声明与实际函数结果也存在漂移。

负责人要求从这些失败提炼结构性问题：建立全局数据和行为契约，消除核心工具之间的特殊格式适配，保留宿主AI选择路线的自由。正确性和实际性能优先，不能仅为开发便利增加对象、校验或依赖。

## 实施顺序与每步出口

### A. 固定原失败、迁移范围和性能基线

盘点工具注册表、公开CLI/Python入口、Recipe、Pipeline、ConstructionTask、文件I/O及实际调用方。每个入口记录接收/输出的对象、注释责任、外部转换与已有使用者，不只清点推荐主线。

保留原失败及独立成功对照；新增反例覆盖负链、复合位置、环状起点、空结果、多产物、歧义和中文路径。期望来自原输入、明确变换或独立事实，不能由待测算法给自己生成答案。

分别绑定旧版/新版提交，在相同解释器、依赖、输入规模和后端下测耗时、内存及可观察的转换/复制次数；CPU计算与Primer3子进程耗时分开。基线阶段写出性能验收预算与理由，实施前固定，不在看到新版结果后改标准。

完成条件：每个需要迁移的公开入口和当前调用方均有去向；原失败能从公开入口重复出现；性能比较方法已确定。

### B. 定义核心契约并贯通首条变换链

按[目标架构](../architecture.md#统一分子契约目标架构)落实模型与行为规则。先贯通完整源记录、提取、DNA变换、文件导出及回读，覆盖原字符串/记录差异。

此步骤可以分批开发，但外层新格式不能掩盖内部错误。每个已迁移工具在其模块内维护实际序列及分子信息，调用方无需补注释或猜坐标。

完成条件：首条链的正反例、来源、注释提取序列、坐标及回读结果均正确；原输入未变。此时只标记已迁移范围，不称整个重构完成。

### C. 完成全入口迁移和特殊适配清理

按A的清单迁移DNA工具、分析工具、多产物反应、Recipe与两个任务入口，更新调用方和必要使用说明。对外命令是否兼容依据真实使用需求确定；内部逐工具产物猜测分支必须删除。

Pydantic是实现候选，不是预定依赖。只有当真实模型需求、声明生成及性能验证证明收益时引入；现有模型能解决问题则复用。JSON Schema表达结构，分子变换不变量仍由对应实现与测试保证。

完成条件：清单中的每项已迁移或有明确删除/兼容去向；存在旧兼容时写实际调用方、位置和移除条件。发布态核心交接只使用一个契约，历史记录保留原版本含义。

### D. 完成交付范围和两项算法修复

根据原请求选择验证范围，验证记录绑定实际材料版本、对象与条件。物理准备结论须来自供给材料或实际模拟操作，不能依据成品序列或模型声明推断。Trace保持旁路，不把未采集的日志变成生物学阻断条件。

元件提取与QC搜索各自保留独立有效、歧义、无解及失效边界。QC改搜索方式，不放宽原温度或结构判据；元件选择修身份规则，不给已知材料设置白名单。

完成条件：T05、T08、T09的原反例和独立边界通过；报告未检查/失败/未知；纯序列设计仍能正确交付，制备请求不会被序列通过替代。

### E. 连续工作流、独立包和最终交接

完成下面的跨工具矩阵、相关全量回归、适用的独立包及Trace三档验证，并比较冻结性能基线。性能回退须定位具体原因；不通过丢注释、跳检查或改验收对象获得速度。

发布包只取审核过的Skill子树，仓库外用生成输入、绝对CLI路径和中文/空格目录运行。先前测试数量和目录迁移CI不能代替新契约的证据。

完成条件：T01至T09逐项核对产物、证据、剩余事项；接口文档与实际运行一致；仅向指定开发分支提交/推送并核对精确提交CI。main不改，正式发布/安装按当时授权另行处理。

## 连续操作验收矩阵

每类至少覆盖独立有效与无效输入；下面是变换类型清单，不是固定生物学路线。不同正确设计可通过。

| 链条 | 独立检查的关键事实 |
|---|---|
| 完整记录 → 元件提取 → 去终止/融合 → 写出回读 | 选择正确；提取链向、读框与域注释正确；完整编码区按任务要求检查 |
| 完整模板 → PCR → 酶切 → 组装 | 最终完整引物产生实际中间体；切点、末端及组装连接与原材料对应 |
| 寡核苷酸 → 退火 → 末端处理 → 下游反应 | 单双链和单链突出端的含义一致；分析结果不能冒充完整分子 |
| 多片段 → 组装 → 验证引物 → 文件交付 | 多产物选择明确；候选组合与实际模板匹配；父本对照和文件检查范围独立 |
| 第一轮落地文件 → 第二轮实际模板 → 再变换 | 实际引用第一轮材料版本，而非仅复制相同序列或回到原亲本 |
| 环状/负链/复合位置 → 切取或旋转 → 保存回读 | 保留生物学片段顺序；部分位点明确标记；源坐标与产物坐标不混用 |
| 制备或检查失败 → 同目录重试 | 旧成功不成为当前结果；原证据与历史文件按现有交付规则保留 |

每条链核对序列、特征位置与提取序列、拓扑、单双链/末端、来源、完整引物、检查范围和实际文件。仅记录返回PASS不足以验收。

通用测试方法仍由[testing](../testing.md)维护。运行环境和可选后端结果单列，不把跳过算通过。开发回归不报告保留评测成功率。
