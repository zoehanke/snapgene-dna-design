## 本轮要得到什么

让用户从真实模板和要求得到可制备、可检查的产物。先处理目标保留、引物与反应链、源注释和交付一致性，再比较宿主表现。Evidence Trace保持旁路。

原会话和失败产物只读保留。归因区分程序缺陷、宿主误用、源注释问题、材料缺口；先复现再改。修改通用接口与契约，不按题号、质粒名或参考答案特判。

## 执行顺序

### 1. 收尾首轮核查

补查第7/9题验证引物、坐标归属、实际GB/DNA和源副本；重新确认独立审核程序自身的链向与环状PCR约定。整理每个问题的可复现命令和证据。

完成条件：明确哪些错误确由现有入口产生，哪些由宿主自写脚本产生。原输入及失败不覆盖。

### 2. 修现有工作流

围绕实际失败改善现有Recipe/Pipeline、目标验证、注释和交付入口。最小修复包括必要的使用示例与轻量工具接口；减少宿主反复手写底层模拟的需要。完整目标由用户请求保留，条件不满足时重新选路或报告未完成。

完成条件：实际源、最终引物、返回中间体及最终文件对应；独立有效和无效反例都能区分。材料注释校订另存、有证据，不改变原DNA或豁免错误。

### 3. 固定评分并验证

先用可读评分表与独立核查程序固定目标、制备、文件、验证、结论五项。必需项未通过或未查不能报整题成功。固定模型、版本、联网、预算及人工介入，保留多轮继承和答案隔离要求。

完成条件：原失败与不同材料/边界的反例回归；真实公开CLI和生成文件核验；相关全量回归、独立包、Trace开关一致性。宿主自然请求与固定参数回放分别记，未实际进行的版本对照不报完成。

### 4. 交付与团队接手

更新使用指南、任务清单、spec和重要历史；打包受测版本，commit/push指定开发分支并核对对应CI，不修改main。

完成条件：包与源码版本一致，下一轮测试者可按自然请求和材料复现。外部试用、湿实验和正式账号提交的资料可接手，但没有真人/实验/提交回执就不勾选完成。
