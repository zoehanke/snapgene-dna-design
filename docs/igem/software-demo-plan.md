# 软件演示计划

目标：证明任务如何变成实际文件，以及记录如何帮助复核。建议4–5分钟；最终视频时长还需遵循[当年交付要求](official-requirements.md)。

| 时间 | 操作 | 证据与讲解 |
|---|---|---|
| 0:00–0:30 | 展示一个明确目标、源文件和约束 | 区分用户要求和AI选择 |
| 0:30–1:15 | 执行quick-start或已预跑的完整任务 | 实际CLI、参数与中间体；不以目标序列充当PCR证明 |
| 1:15–2:00 | 打开输出GB/.dna与引物表 | 序列、拓扑、注释、结合位点；组件与正式构建身份不同 |
| 2:00–3:00 | 打开Trace，点选择、来源、文件 | 理由/支持/反对/条件各归其主；原验证对象可回查 |
| 3:00–4:00 | 展示独立无效元件/错误注释被拒绝 | 验证失败无正式交付，保留实际错误，不表演强行变绿 |
| 4:00–4:30 | 展示记录变化与后续限制 | 重查建议不自动改科学结论 |

最小公开输入是 fixtures/synthetic/tagging_params.json；其产物是component，不能伪装成完整克隆。完整演示采用 `python scripts/demo_engineering_cycle.py --out-dir output/demo-new`：对2500bp合成源的GFP第二密码子作AGT→AGC同义改变，真实运行inverse PCR配方，核对其余DNA、蛋白翻译、注释和四份交付文件，生成可读Trace。脚本中的路线由演示作者预设，明确告诉观众，不冒充现场AI选择。现场先完整预跑。

预计简单CLI为秒级，精确数值看本机benchmark；复杂primer/大文件可能更久。离线备份带输入、命令、输出和报告，用公开合成案例；现场失败时明确播放预录实际执行，而非假装直播成功。

应录屏：首次运行、一次真实失败、完整文件与Trace回溯。应截图：任务参数、产物注释、证据关系及检查边界。当前截图与缺口见[evidence inventory](evidence-inventory.md)，无真实录屏则标MISSING。
