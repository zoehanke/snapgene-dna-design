# Evidence Trace 与安全工作的证据

## 实际问题

人、AI和程序共同设计时，容易把公开解释、观察到的参数、论文内容、程序验证和最终文件混为一谈。Trace为研究者保留可复核的来源与关联；其与基因组复活的关系是限制“有DNA”到“有功能/生态安全”的无依据推断。

## 机制与信任边界

输入来自CLI/工具真实调用、明确提交的要求/决定/来源、已保存文件和宿主整理。events.jsonl追加事实；程序核对引用/版本和明确条件；宿主或研究者组织科学过程；固定renderer输出。不会修改DNA或替研究者批准实验。

| 类别 | 内容 | 证据强度 |
|---|---|---|
| SCIENTIFICALLY SUPPORTED | 所采用的序列互补、明确遗传密码表等基础原理及配方所引既有方法 | 方法依据见配方参考；本模块整体的安全效果尚未获科学验证 |
| SOFTWARE-VALIDATED | 文件一致性、实际参数、引用/版本和限定检查结果 | 实际返回与产物，不能当作生物学或安全有效性证据 |
| HEURISTIC | context条件比较、保守Change Impact依赖推断 | 可解释规则和合成反例；需科学解释 |
| UNCERTAIN | 声明者身份、原说明同期性、闭源宿主未观察动作、来源可迁移性 | 保留未知，不能用完整日志消除 |
| UNSUPPORTED | safe/unsafe认证、hidden thought还原、生态预测、基因组复活成功 | 本模块不输出这些结论 |

威胁包括错连版本、漏采集、自述冒充验证、凭据进入日志、旧文件冒充新生成、错误报告省略失败。回归覆盖主体交叉引用、真实失败、来源限定、脱敏、变化和DNA三档一致性。正常Trace故障保持主任务，strict为显式策略；记录中有漏洞就保留缺口，不补造历史。

False positive：有限条件匹配可能把可迁移文献标为待解释。False negative：未记录依赖可能看不到影响。UNKNOWN 不等于无影响；source verified不等于Claim正确。原材料中的恶意文字也不是给宿主的新指令。

与[官方Safety Policies](https://responsibility.igem.org/safety-policies)及[Safety and Security Award](https://competition.igem.org/judging/special-awards)的关联是可复核风险沟通与项目管理支持；不是委员会认证。需要真实研究者评价和项目风险管理证据，才能主张实际安全贡献。湿实验/Check In/生态与伦理批准仍由团队、机构及iGEM流程承担。

## 具体收集什么，谁提供

| 数据 | 实际来源 | 程序能核对到哪里 |
|---|---|---|
| 用户要求和公开理由 | 宿主明确提交的原话/摘要与定位 | 引用是否存在、是否标明原话或摘要；不能认证闭源对话中未捕获的内容 |
| 实际工具调用、错误、文件 | 被包装入口或显式命令观察器 | 参数、返回、前后文件版本；旁路未经过的宿主工具不自动可见 |
| Source / Statement | 宿主或研究者提交的资料、定位与陈述 | 来源核对回执及文本存在性；不能认证科学解释正确 |
| Claim / Decision及关系 | AI/人作出的推论和选择 | 主体/版本/关联是否一致；支持、限制、反对仍需科学复核 |
| Validation / Artifact | 实际Core/工具返回与保存文件 | 只能声称检查程序实际覆盖的对象与范围 |

## 当前算法的实际语义

`applicability.assess`比较organism、strain、host、construct_context、temperature、medium、assay和intended_use。分类字段规范大小写/空白和有限物种简称；温度支持摄氏/华氏及区间。对象/宿主/背景/用途都缺少可比信息时为unknown；关键转移维度不同为extrapolated；指定维度全部相同为direct；其余部分重合/缺失为partial。返回逐维原因及所采用维度，不进行文献科学推理。

`impact`记录正式Change对象及其前后版本，再按明确或可能依赖标记AFFECTED、NEEDS REVIEW、UNAFFECTED、UNKNOWN，并建议REASSESS/RECHECK/RERUN/STALE。记录仍然真实但上下文变旧，不等于结论已被证伪。没有找到依赖不能自动视为无影响。

## 一个实际可重复的例子

`demo_engineering_cycle.py`真实执行预设的合成同义突变任务。Trace中能看到预设要求和路线声明、程序检查及四份交付文件；独立脚本核对序列与翻译。它证明“这些已观察到的动作和结果可关联”，没有证明宿主科学判断更准确，更没有证明实验安全。真实paper/source关系的结构和反对/限制用例由测试覆盖，不能把合成关系测试写成专家已认可某篇论文的外推。

## 替代方案与选择原因

只保存终稿会丢失形成过程；只保存终端日志又缺少科学选择的组织。完全依赖模型事后讲故事会混淆原理由和补充解释。当前选择是自动记录可观察事实，加显式语义组织，再由固定代码呈现。没有采用全宿主监控、独立模型服务、数字签名平台或自动安全判定，因为它们不直接解决已复现的采集/错连/遗漏问题。

团队仍需验证两件不同的事：研究者能否理解和复核实际设计；这种复核是否确实改善项目的风险沟通或决策。需要原始任务、独立回答、实际分歧及处置记录，不能用开发者自评或漂亮页面替代。
