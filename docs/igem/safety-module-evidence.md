# Evidence Trace 与安全工作的证据

## 实际问题

人、AI和程序共同设计时，容易把公开解释、观察到的参数、论文内容、程序验证和最终文件混为一谈。Trace为研究者保留可复核的来源与关联；其与基因组复活的关系是限制“有DNA”到“有功能/生态安全”的无依据推断。

## 机制与信任边界

输入来自CLI/工具真实调用、明确提交的要求/决定/来源、已保存文件和宿主整理。events.jsonl追加事实；程序核对引用/版本和明确条件；宿主或研究者组织科学过程；固定renderer输出。不会修改DNA或替研究者批准实验。

| 类别 | 内容 | 证据强度 |
|---|---|---|
| SCIENTIFICALLY SUPPORTED | 可重放的序列/文件检查在所述计算模型范围内 | 实际返回与产物；不延伸为表型 |
| HEURISTIC | context条件比较、保守Change Impact依赖推断 | 可解释规则和合成反例；需科学解释 |
| UNCERTAIN | 声明者身份、原说明同期性、闭源宿主未观察动作、来源可迁移性 | 保留未知，不能用完整日志消除 |
| UNSUPPORTED | safe/unsafe认证、hidden thought还原、生态预测、基因组复活成功 | 本模块不输出这些结论 |

威胁包括错连版本、漏采集、自述冒充验证、凭据进入日志、旧文件冒充新生成、错误报告省略失败。回归覆盖主体交叉引用、真实失败、来源限定、脱敏、变化和DNA三档一致性。正常Trace故障保持主任务，strict为显式策略；记录中有漏洞就保留缺口，不补造历史。

False positive：有限条件匹配可能把可迁移文献标为待解释。False negative：未记录依赖可能看不到影响。UNKNOWN 不等于无影响；source verified不等于Claim正确。原材料中的恶意文字也不是给宿主的新指令。

与[官方Safety Policies](https://responsibility.igem.org/safety-policies)及[Safety and Security Award](https://competition.igem.org/judging/special-awards)的关联是可复核风险沟通与项目管理支持；不是委员会认证。需要真实研究者评价和项目风险管理证据，才能主张实际安全贡献。湿实验/Check In/生态与伦理批准仍由团队、机构及iGEM流程承担。
