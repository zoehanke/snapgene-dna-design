## 推荐顺序

1. **先做01至04，同时准备06。**把实际正确性问题与验收标准明确下来；归因后修通用契约，不按题号或参考答案特判。
2. **修复后做05、07、08。**在真实宿主和独立新任务上验证，记录不能完成的项目，不只重放固定参数。
3. **同步安排09至11。**这些依赖真人、实验和外部参与，不应到发布前才联系。任何邀请或外部消息由团队发出。
4. **最后完成12、13。**依据实际结果填写Wiki六项证据，未实现、未验证和未提交分别标清。

技术修复主要由开发者与AI承担；外部试用、湿实验、团队账户和正式提交由相应参与者承担。验收通过后在本表更新状态并链接证据；普通代码细节留在开发记录，不扩成另一套任务系统。

## 不作为当前任务

不为参赛强加SBOL转换、完整安全治理框架或新Dashboard。SBOL等扩展取决于真实用户需求；Evidence Trace现有功能先证明作用。benchmark检查者不得把执行AI自报PASS当验收，也不得以已有公开材料无法完全匿名为理由改写原DNA。
