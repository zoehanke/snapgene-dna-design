# 真实任务测试：怎样评分

2026年10月3日 · 第2版 · 本目录九题全部属于开发回归，不能改名后称为保留评测。

2026-10-13公开状态修订：两份题面/答案资料已经公开，现移出当前公开树并在仓库外保留原件。它们仍可从历史、缓存或fork取得，永远不再作为未接触评测；移动目录、删除当前文件或未来重写历史均不能恢复盲测资格。只可作为已知题开发回归，独立heldout须使用另行管理的新材料与答案。

**主问题：研究者能否用这次交付继续完成原任务？**不按报告长度、工具次数或AI自报PASS评分。

## 每题检查五件事

| 项目 | 通过意味着什么 |
|---|---|
| 目标 | 必需元件、方向、读框、指定变化和排除项均满足原要求 |
| 制备 | 最终引物在实际模板上成立，中间体及后续反应得到最终序列 |
| 文件 | 要求的格式、注释、源副本与引物表正确，文件之间一致 |
| 验证 | 方案能区分本题的正确产物、亲本及主要错误 |
| 结论 | 交付状态真实，下一步明确，没有影响操作的错误解释 |

各项记为“通过、失败、未核查、不适用”。**适用的必需项全部通过，整题才通过。**未核查不算通过；也不把它悄悄剔除后报告高成功率。

第1题是材料核查，不要求新的PCR制备或构建文件。第2至9题均要检查完整制备和文件。第4、8题两轮合起来算一题，第二轮必须继承第一轮实际产物。第10题材料未齐，不发、不评分。

不同正确路线、引物和环形起点可接受。关键序列、接口、元件和蛋白变化按题目精确核对；整体95%相似不能掩盖一处关键错误。

## 谁来检查

程序从原输入、最终订购引物和实际文件重算序列、反应及坐标；不以被测Skill给自己的检查报告代替独立核查。真人检查生物学取舍、材料可行性和交付解释，争议保留证据后复核。

评分表只给检查者。每条通过或失败都链接对应文件、调用记录或检查结果。AI可以辅助收集证据，不作为唯一裁判。

## 测试条件先固定

开发者可看回归题和失败记录。保留题由独立评测者管理，材料、答案、参考产物、逐题反馈均不向开发者开放。当前没有完成隔离保留评测，不报告通用任务成功率提高。

正式评测前保存冻结记录：代码commit、包SHA-256、评分规则版本/哈希、依赖、模型设置、工具、联网、预算、计划重复次数与帮助条件。只给执行者当前自然请求和必要原始材料；答案、评分脚本、开发记录、历史解题会话均留在受限检查者环境。

新对话、另一个目录或“别看答案”提示不等于隔离。独立评测者须检查执行工具实际能否读取共享目录、旧会话、连接器及网上答案；运行权限按受控账号/虚拟环境限制，检查时可用不含答案的哨兵文件证明权限。答案泄漏保留日志，标为污染；不计保留评测。不能证明训练先验未见材料时，不宣称绝对盲测。

- 记录题目与材料包版本、模型与推理设置、Skill源码/包版本、运行环境和可用工具。
- 使用新的对话与工作目录，只给当前轮自然请求及必要材料；不预填planner或操作参数。
- 本轮采用允许功能/协议查询的联网条件，检查者答案和参考成品不进入执行环境。若材料仍可能被识别，如实说明；发现实际答案泄漏则单列污染记录，重新执行。
- 无Skill、旧版、新版使用同一宿主模型、材料、预算和帮助条件。人工更改参数或解释答案算接管，不算独立成功。
- 执行者以外的开发者、Reviewer或审查AI改注释、路线、参数或引物，均记录介入。校订输入后的成功另列，不能计原始材料独立成功。执行模型自身设计过程与外部帮助分别记录；正常生成中间体不等于校订原输入。
- 每题运行次数和资源上限在开始前记录；未经确认先做一次小范围试运行，不据此报告稳定性。重复试验每次独立启动，不能挑最好的一次。
- 材料缺口或无解目标在发题前审查；确有题目问题时说明并更正版本。模型犯错不能成为删除题目的理由。

## 结果怎样报

主指标为**完整任务成功率**。分项结果解释错在哪里；成本单列。成功任务与失败任务的耗时分别统计，避免把很快失败说成效率高。

记录实际运行耗时、输入/输出token、可见缓存信息和人工接管。多轮任务不把等待用户发第二轮的时间算作模型执行；缺统计就写未取得，不能填0。

有重复试验后，再报告平均成功率及“同题三次全成功”的比例。样本数量、未核查项和无效/污染运行一起公布。九题回归支持的是这组任务，不代表所有DNA设计都已可靠。

## 最小落地方式

使用[评分模板](../../benchmarks/host-readiness-v0.1/scores-template.csv)填检查结果，再用现有的独立序列/反应核查补证据。不需要新建评测平台。

脚本`python scripts/summarize_host_scores.py --scores scores.csv`只汇总检查者填写的结果，不替代生物学验证。回归/试用、原始/校订输入和不同冻结记录分别汇总。只有原始输入、已声明隔离与冻结的保留评测全部完成时才输出正式成功率；这些声明的真实性仍由独立检查者负责。

`human_interventions`必须记录；空白表示未取得，不等于0。所有技术项通过但经人工接管的运行标为`ASSISTED`，不计独立成功。未核查项、缺题或不均衡重复仍保留在结果中，不输出整套正式成功率。

CSV新增四列：`evaluation_kind`填写`development_regression / host_pilot / heldout`；`input_condition`填`original / corrected`；`isolation_status`填`verified / unverified / contaminated`；`freeze_record`引用冻结记录。旧CSV缺这些列按未知处理，不能自动升级为保留评测。当前模板预填开发回归，评分项未核查。

保留评测可用独立检查者持有的适用项文件，经`--applicability`传入，不把它放进执行包。私有全报告只给检查者；反馈开发者时使用`--aggregate-only`，仅输出总数和目标/制备/文件/验证/结论错误类别，删除题目ID、逐轮成绩及证据路径。污染和所有重复记录保留，不挑最好一次。

旧版对没有来源或明确污染的全PASS记录也输出1.0，是本轮已复现的统计缺陷。增加上述资格检查是收紧报告要求，不修改任何题目的生物学目标、通过阈值或既有失败输入。

方法参考：[LABBench2的真实PCR/组装验证](https://github.com/EdisonScientific/labbench2/blob/main/src/labbench2/cloning/rewards.py)、[τ-bench的独立重复试验](https://arxiv.org/html/2406.12045v1)。本项目采用自己的精确目标与交付标准，不直接照搬相似度阈值或回答字符串匹配。
